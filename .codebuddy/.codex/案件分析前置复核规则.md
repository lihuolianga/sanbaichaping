# 案件分析前置复核规则

每次分析“新的案件”之前，必须重新核对当前工作区，不得直接沿用历史报告、旧记忆或旧规划文件中的章节边界。

| 不要 | 必须做 |
|---|---|
| 直接相信上次记录的“正文到第X章” | 用 `rg --files` 或等价方式重新枚举各卷正文文件 |
| 只检查已跟踪文件 | 同时检查未跟踪文件和 `git status --short` |
| 由卷纲决定“新的案件” | 先找当前最高正式正文，阅读末章实际钩子，再对照卷纲 |
| 把旧 `findings.md` 当现状 | 把旧记录视为历史数据，发现冲突时以当前物理文件和正文为准 |
| 看到第316章旧报告就停止 | 检查第317章及以后是否存在，再确定真正的新案件 |
| 把计划或提示词说成已执行正文 | 分开报告已写正文、卷纲计划和未写章节 |

最低检查项：

1. 当前正式正文最高章节号。
2. 最高章节号对应的真实文件路径。
3. 是否存在未跟踪的新章节。
4. 最高章节末尾实际引出的案件。
5. 该案件的正文文件是否已经存在。
6. 与卷纲中的案件编号是否一致。
